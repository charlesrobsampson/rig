**Before any task: read `process.md` (how to work), the sections of `manifest.md` the task names (design intent), and the sections of `docs/formats.md` it names (exact shapes). Also read `Notes:` on the tasks you depend on.**

Tasks are in dependency order. Each task = one branch (`task/NN-slug`). Tick the box only in the task's final commit. Task fields: **Session** (resume command, filled when started) · **Depends** · **Read** · **Build** · **Tests** · **Manual check** · **Notes** (filled at finish for the next task).

Conventions: module `github.com/charlesrobsampson/rig`; packages per manifest §6 (task 01 reconciles the layout, adding `clock`, `store`, `state`, `contract`, `policy`, `testkit`); fakes live in `internal/testkit`.

**MVP cut:** tasks 01–32 give tickets, isolated checkouts, gated lifecycle, agents in Herdr/tmux panes, message injection, and `rig list`. Docker (33–44) is next.

### 13 · Daemon server lifecycle
- [x] Done
- Session: `claude --resume b7893019-4d34-49ee-8e94-32c09cddc9c4`
- Branch: `task/13-daemon-server` · Depends: 11, 12
- Read: `manifest.md` §6, `process.md` §4 (sockets)
- Build: `internal/daemon` server: unix socket (path configurable), PID file, single-instance lock, context-driven graceful shutdown, stale socket/PID cleanup, request router with handler registry.
- Tests: second server on the same socket fails with a clear error; stale PID/socket recovered; shutdown closes connections and removes socket; unknown method handled; concurrent clients.
- Manual check: none.
- Notes: `daemon.Listen(daemon.Options{SocketPath, PIDPath, Version, Clock, Logger, ShutdownGrace})` takes the single-instance lock and binds the socket, then `srv.Serve(ctx)` blocks until the context is cancelled or `srv.Stop()` is called (split so callers can report startup errors synchronously). The pid file is locked with `flock` for the daemon's whole life, and *the lock, not the pid, decides liveness*: a crashed daemon's leftover pid file is taken over and its leftover socket removed, but a live daemon makes `Listen` fail with `daemon already running (pid N, pid file ...)` before anything is touched; a path that exists and is not a socket is never deleted. Socket and pid file directories are created `0700`, the socket `0600`; socket paths over 103 bytes are rejected with a clear message. Registry: `srv.Handle(method, func(ctx, params json.RawMessage) (any, error))` for unary methods and `srv.HandleStream(method, func(ctx, params, send func(any) error) error)` for `events.subscribe`/`logs.stream`; both panic at registration for undocumented or wrong-kind methods. A handler's `*api.Error` reaches the client unchanged, any other error becomes `internal`, a panic is recovered into an `internal` error. The command goes as separate arguments, which tmux runs without a shell, so no quoting is needed. `remain-on-exit on` is set in the same invocation as the spawn (tmux handles process exit only after the whole command line ran, so even an instantly-exiting command is kept). **PaneID** is tmux's `%N`; anything not matching `^%[0-9]+$` is `ErrNotFound` before tmux is called (no option injection). Ticket ids with `.` or `:` are `ErrInvalid` (tmux rewrites/uses them). `Ready` only checks the binary and requires tmux 3.2+ (`-e` on `new-session`); it starts no server (the first spawn does; the server exits with its last pane, like Herdr leaving nothing behind). Finished panes stay listed with `Alive=false` and `ExitStatus` (Herdr drops them; callers handle both); typing into one is `ErrNotFound`. No server means an empty list, not an error. `SendText` is `send-keys -l -t <id> -- text` for short single-line text and a bracketed paste (`load-buffer` from stdin, `paste-buffer -p -d`) for multi-line or over 512 bytes; `Submit` is `send-keys Enter`. `Read` is `capture-pane -p` (history for N lines, last N non-trailing-blank lines). `Heuristic` is `heuristic(screen)` on the last 25 screen lines: a "Do you want to" dialog with a numbered list is blocked (wins over a stale working line), `esc to interrupt` is working, the input box (`? for shortcuts`, box border, prompt) is idle, anything else unknown; a plain shell stays unknown on purpose. `Attach` best-effort selects the window and returns `tmux -L <socket> attach -t =<ticket>`. **Selection:** `backends.New(name)` (`internal/terminal/backends`) maps `defaults.terminal_backend` (`""`/`herdr`, `tmux`; else an error naming both); task 31 wires it into the daemon. **Tests:** default: heuristic table on synthetic screens, version parsing, Ready/refusal/pane-id/no-server/argument checks against a fake `tmux` script (never the real one), selector; integration (real tmux, private `rig-itest-*` socket, `kill-server` cleanup): the whole contract suite with `RunsProcesses:true`, plus tmux-specific cases the contract cannot require: kept pane with exit status 7, key names typed as text (`Enter`, `C-c`, `-n`, `--`) stay text, and the screen heuristic on a real pane. Mutation checks: dropping `remain-on-exit`, `-l`, or `--` each fails an integration test.
